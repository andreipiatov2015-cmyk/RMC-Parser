# Сбор текстового корпуса сайта — инструкция по запуску

Добавлено четыре новых файла (папка `src/main/java/com/rmc/corpus/`):

- **CorpusCollectionService.java** — целевой сбор по разделу программ
  (фаза A: карточки, фаза B: детальные страницы программ).
- **CorpusCollectionRunner.java** — запуск целевого сбора.
- **SiteCrawler.java** — универсальный обход **всего сайта**: идёт по
  всем найденным ссылкам `<a href>` в пределах одного домена, не
  привязан к разделу `/programs/`. Так собираются и разделы
  учреждений, и всё остальное, что найдётся по ссылкам.
- **FullSiteCrawlRunner.java** — запуск полного обхода.

Это два независимых инструмента — можно пользоваться либо одним, либо
обоими сразу (данные не пересекаются, лежат в разных подпапках).

Ничего в существующих файлах проекта не менялось — это безопасное
дополнение, собирается вместе с остальным проектом как есть.

---

## Вариант 1 — запуск через IntelliJ IDEA (проще всего)

1. Откройте проект в IntelliJ IDEA как обычно (он сам подтянет
   зависимости через Maven, если раньше уже собирался).
2. В дереве проекта найдите
   `src/main/java/com/rmc/corpus/CorpusCollectionRunner.java`.
3. Откройте файл, нажмите на зелёный треугольник слева от `main(...)`
   → **Run 'CorpusCollectionRunner.main()'**.
4. Первый запуск завершится ошибкой — нужно передать логин и пароль
   как аргументы программы. Откройте
   **Run → Edit Configurations → CorpusCollectionRunner**, в поле
   **Program arguments** впишите:
   ```
   ваш_логин ваш_пароль
   ```
5. Запустите ещё раз.

## Вариант 2 — запуск из командной строки (Maven)

```bash
cd RMC-Parser
mvn compile
mvn dependency:build-classpath -Dmdep.outputFile=cp.txt
java -cp "target/classes;$(cat cp.txt)" com.rmc.corpus.CorpusCollectionRunner ваш_логин ваш_пароль
```

(На Windows в PowerShell разделитель classpath — `;`, как в примере
выше; если используете cmd.exe — тоже `;`.)

## Что произойдёт при запуске

1. Программа авторизуется на сайте под вашим логином.
2. Пройдёт по всем страницам списка программ (защита от зацикливания —
   максимум 500 страниц), как это уже делает раздел анализа.
3. **Фаза A** — мгновенно сохранит текст карточек в
   `data/raw/cards/{id}.txt`.
4. **Фаза B** — начнёт долгий обход: зайдёт на страницу каждой найденной
   программы и сохранит её полный текст в `data/raw/details/{id}.txt`.
   Между запросами пауза 400 мс, чтобы не перегружать сайт — на
   несколько тысяч программ это может занять от получаса до нескольких
   часов, в зависимости от объёма сайта.

Можно смело прерывать процесс (Ctrl+C или Stop в IDE) и запускать
заново позже — уже скачанные файлы не перекачиваются повторно
(проверяется, существует ли файл).

## Необязательный третий аргумент

Если нужно собрать не весь сайт, а только программы по конкретным
фильтрам — передайте query-строку фильтров третьим аргументом (тот же
формат, что строит `FilterSession.buildQueryString()` в интерфейсе):

```bash
java -cp ... com.rmc.corpus.CorpusCollectionRunner логин пароль "direction=5&age=7-10"
```

## Полный обход сайта — по уровням (SiteCrawler)

Работает независимо от целевого сбора выше — запускается отдельным
классом `FullSiteCrawlRunner`. Специально сделан **поэтапным**: не
проваливается сразу в тысячи страниц программ, а сначала строит карту
структуры сайта, уровень за уровнем, и останавливается там, где вы
скажете.

**Как это работает по уровням:**
- Уровень 0 — главная страница
- Уровень 1 — всё, на что прямо ссылается главная (обычно это и есть
  меню — муниципалитеты, разделы, вкладки)
- Уровень 2 — то, на что ссылаются страницы уровня 1
- и так далее

Раздел программ (`/programs/`, `/program/`, `/course/`) — если он
встретится — **сохраняется, но не разворачивается вглубь** ни на каком
уровне: сама страница списка попадёт в корпус, но переход по тысячам
отдельных программ не начнётся, пока вы не запустите это отдельно
через `CorpusCollectionRunner`.

**Запуск (в IntelliJ IDEA):** откройте
`src/main/java/com/rmc/corpus/FullSiteCrawlRunner.java`, запустите
через зелёный треугольник рядом с `main()`, затем в
**Edit Configurations** впишите в Program arguments:
```
ваш_логин ваш_пароль 1 500
```
Здесь `1` — глубина (сколько уровней от главной пройти), `500` —
общий потолок страниц на всякий случай. Если аргументы не передать,
по умолчанию используется глубина 1 и лимит 500 страниц — этого
достаточно для первого раза, чтобы просто увидеть структуру.

**Результат первого запуска:**
- `data/raw/site/_sitemap.txt` — список всех найденных страниц с
  заголовками и уровнем вложенности. **Откройте этот файл первым** —
  это и есть карта сайта, ради которой всё затевалось.
- `data/raw/site/*.txt` — текст каждой отдельной найденной страницы

**Дальше — решаете сами, куда двигаться:**
- Если в sitemap видно, что интересующие разделы лежат на уровне 2
  (например, "муниципалитет → школа") — запустите ещё раз с
  `ваш_логин ваш_пароль 2 1500`, глубже. Уже собранные страницы
  уровня 0–1 не перекачаются заново.
- Программы (последний этап, как и договаривались) собираем отдельно
  через `CorpusCollectionRunner` — он один раз проходит список через
  правильную пагинацию, без риска дублей и без лишней нагрузки на
  вложенные разделы школ/садов.

**Про нагрузку на сайт:** между запросами пауза 350 мс — то есть
максимум около 3 запросов в секунду, но при большом количестве
страниц (сотни-тысячи) это всё равно заметно администраторам сайта.
Поскольку сайт — региональный/муниципальный портал, стоит заранее
уточнить у администраторов сайта, что вы планируете делать
автоматизированный сбор, и на всякий случай проверить, нет ли
готового официального способа получить данные (экспорт, API) —
это надёжнее, чем гадать по реакции сайта постфактум.

## Дальше

Когда `data/raw/cards` и `data/raw/details` наполнятся текстом — это и
будет корпус для индексации (следующий шаг: превратить его в вектора
через `sentence-transformers`/`faiss`, уже на Python-стороне при
подготовке модели, либо сразу через Java-эквиваленты — обсудим
отдельно, когда дойдём).

Когда всё будет проверено и стабильно — вызовы `CorpusCollectionService`
можно будет перенести в `WorkspaceContainer`/`FiltersView` и повесить
на обычную кнопку в интерфейсе вместо отдельного запуска.
