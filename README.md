# RMC Framework

Десктопное приложение для анализа данных портала дополнительного образования
[rmc.ruobr.ru](https://rmc.ruobr.ru) (административная система учёта программ,
сертификатов и организаций дополнительного образования Кемеровской области).

Программа авторизуется на портале под учётной записью пользователя, находит
образовательные программы по заданным фильтрам (муниципалитет, категория
потребителей, статус зачисления и т.д.), собирает показатели по найденным
программам и учреждениям и выгружает результат в Excel.

## Стек технологий

- **Java 21**, **JavaFX** — интерфейс
- **Maven** — сборка (`pom.xml`)
- **Jsoup** — разбор HTML-страниц портала
- **Apache POI** — экспорт в Excel (`.xlsx`)
- **java.net.http.HttpClient** — все сетевые запросы к порталу и к GitHub
- **jpackage + WiX Toolset** — сборка Windows-установщика (`build-installer.bat`)
- **[Tabler Icons](https://github.com/tabler/tabler-icons)** (MIT) — иконки интерфейса. Не отдельная библиотека, а свои классы `ui.icons.TablerIcon`/`TablerIcons`, которые строят JavaFX-узел (`SVGPath`) из исходных данных иконок Tabler — так иконки красятся через CSS и следуют теме оформления

## Как это устроено

### 1. Авторизация

- `auth.django.DjangoAuthenticationProvider` — логин в стиле Django
  (GET страницы входа → извлечение CSRF-токена → POST логина и пароля).
- `auth.account.AccountStorageService` / `SavedAccount` — хранение сохранённых
  учётных записей на диске, чтобы не вводить пароль каждый раз.
- `http.HttpClientService` / `SessionManager` — обёртка над Java `HttpClient`
  с cookies и таймаутами.

### 2. Фильтры и поиск

- `filters.*` — построение и разбор фильтров портала (муниципалитет,
  категория, статус и т.д.) в query-строку `/programs/?...`.
- `parser.ProgramParser` — разбор списка программ (с постраничным обходом).
- `parser.ProgramDetailParser` — разбор страницы отдельной программы,
  включая блоки показателей `.statistic` (зачисления по бюджету/сертификату/
  платным местам и т.д.).
- `parser.OrganizationStatsParser` — разбор страницы учреждения целиком (та
  же разметка `.statistic`, но в масштабе всего учреждения, а не одной
  программы). Подписи показателей нигде не захардкожены — оба парсера берут
  ровно те подписи, что реально есть на странице, поэтому переживают
  изменения разметки сайта.

### 3. Анализ и статистика

Это ядро приложения — `search.service.ProgramAnalysisService`. Для каждого
найденного (по фильтру) учреждения считаются **два независимых набора
показателей одновременно**:

- **По фильтру** — суммируются показатели только тех программ учреждения,
  что реально прошли фильтр (например, только программы для детей с ОВЗ).
  Плюс синтетический показатель «Программ по фильтру» — сколько таких
  программ у учреждения.
- **По учреждению целиком** — показатели со страницы самого учреждения, без
  учёта фильтра (это исходная логика подсчёта, использовавшаяся в версии
  `0.1.8`).

Оба набора хранятся в `search.model.InstitutionAnalysis` и
`search.model.AnalysisResult` раздельно (`getFilteredStats()`/
`getOverallStats()`). Какие из показателей показать на экране, решает
пользователь — через сворачиваемый список галочек «⚙ Показатели» в
`ui.workspace.views.ResultsView`. Список строится динамически из реально
пришедших от сайта подписей, выбор сохраняется между запусками через
`search.service.StatDisplayPreferences` (Java Preferences API, реестр
Windows).

### 4. Интерфейс

- `ui.MainWindow`, `ui.workspace.WorkspaceContainer` — каркас окна,
  переключение экранов через `WorkspaceState`.
- `ui.workspace.views.*` — экраны: `AuthView` (вход), `FiltersView` (выбор
  фильтров), `ResultsView` (результаты анализа), `FavoritesView` (избранные
  учреждения), `InstitutionDetailView` (карточка учреждения), `RmcAiView`
  (заготовка будущего AI-чата), `LoadingView`, `ErrorView`.
- `ui.navigation` — боковое меню.

### 5. Экспорт

- `export.ExportService` — выгрузка результата анализа в `.xlsx` (два листа:
  «Итого» и «По учреждениям»), включает оба набора показателей целиком,
  независимо от того, что выбрано галочками на экране.

### 6. Обновления

- `update.UpdateCheckService` — проверка новой версии через GitHub Releases
  API отдельного репозитория
  [`RMC-Parser-public`](https://github.com/andreipiatov2015-cmyk/RMC-Parser-public)
  (это репозиторий-«витрина» только для релизов, не зеркало исходного кода).
  Сравнение версий — `version.VersionService`/`VersionComparator`, обычное
  числовое сравнение `major.minor.patch`, поэтому новый релиз обязан иметь
  тег строго больше текущей версии приложения.

### 7. Задел на будущее — сбор корпуса и локальный ИИ

- `corpus.SiteCrawler`, `CorpusCollectionService` — обход сайта для сбора
  текстового корпуса (для будущего чат-бота с ответами по данным сайта и
  законодательству).
- `ai.*` (`EmbeddingService`, `VectorIndex`, `RagSearchService`,
  `RagQueryRunner`, `AiAgentInstallService`) — заготовка Java-нативного
  RAG-поиска (эмбеддинги через ONNX Runtime прямо внутри JVM, без Python в
  рантайме) и загрузки AI-модели отдельно от основной программы. Пока не
  реализовано полностью — по этой части параллельно велась разработка на
  Python-прототипе.

## Сборка и запуск

```
mvn clean package
```

Установщик под Windows (`.exe`, через jpackage + WiX Toolset v3) —
`build-installer.bat`, требует JDK 21+ со встроенным JavaFX (например
BellSoft Liberica Full или Azul Zulu FX — обычный OpenJDK этого не умеет).

## Структура репозиториев

- **`RMC-Parser`** (этот репозиторий) — исходный код.
- **`RMC-Parser-public`** — только метаданные релизов для автообновления,
  без исходного кода.
